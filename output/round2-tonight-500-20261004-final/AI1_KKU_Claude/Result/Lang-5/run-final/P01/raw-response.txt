- `toLocale(String)`: valid formats "en", "en_GB", "en_GB_VAR" must parse correctly; null input should throw NullPointerException; malformed strings (wrong case, wrong length, bad separators) should throw IllegalArgumentException; boundary around 2-letter vs 3-letter language codes, and empty country with variant (e.g. "en__POSIX") should be accepted.
- `languagesByCountry(String)`: null or unknown country code should return empty (non-null) list, not throw; valid country code (e.g. "GB") should return list containing locales with that country and a language set; result list must be unmodifiable; repeated calls should return same cached/equal content.
- `countriesByLanguage(String)`: same contract as above but keyed by language code (e.g. "en"); null/unknown language returns empty list; result unmodifiable.
- `localeLookupList(Locale)` and `localeLookupList(Locale, Locale)`: null primary locale should return empty list (or NPE per contract—verify against javadoc); list must start with the most specific locale and progressively drop variant, then country, then language; must include default locale at end when provided; no duplicate entries; returned list unmodifiable.
- `availableLocaleList()`/`availableLocaleSet()`: must be non-empty, contain `Locale.getDefault()` or at least standard locales like `Locale.US`; returned collections unmodifiable; set and list should contain same elements.
- `isAvailableLocale(Locale)`: true for locales in `availableLocaleList()`, false for a clearly bogus locale (e.g. new Locale("xx","XX")); null should return false (per typical contract) rather than throw.
- Static initializer (`cLanguagesByCountry`, `cCountriesByLanguage`) must be lazily/correctly populated exactly once — verify no `ConcurrentModificationException` or stale caching across multiple calls with different/same keys.
- Verify thread-safety is not directly testable but consistency across repeated calls (idempotence) can be asserted.
