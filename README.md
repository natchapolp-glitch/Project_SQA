# SQA Project: Automated Unit-Test Generation on Defects4J

This repository contains the implementation and experimental evidence for CP353201.
It compares four ways to generate Java unit tests on Defects4J:

1. CMA-ES (search-based test-data generation)
2. FSCS-ART (Adaptive Random Testing)
3. Claude-generated tests
4. AI Sphere / IntelliSphere-generated tests

The round-1 report and the original Defects4J README are retained under `docs/`.

## Current status

The reproducible `Lang-1` smoke pilot is complete: metadata and baseline logs
exist for both revisions. Its immutable current run is
`results/raw/Lang/1/differential-v3/20260920T000500Z/`: FSCS-ART produced 21

## Prerequisites

Run Defects4J in Ubuntu/WSL. Defects4J 3.0.1 requires Java 11, Git, Subversion,
Perl, `cpanm`, and the Perl modules listed by Defects4J. Test execution must use
the `America/Los_Angeles` timezone.

Check a prepared Linux environment with:

```bash
bash scripts/setup/check-environment.sh
```

This workspace's WSL environment is ready: Java 11, Subversion, Perl modules,
and Defects4J 3.0.1 are installed. The scripts resolve the repository-local
`defects4j/framework/bin/defects4j` executable directly, so no global PATH edit
is required.

## Pilot workflow

1. Validate candidates in `dataset/pilot-candidates.csv` after Defects4J is installed.
2. Record the chosen reproducible bugs in `dataset/selected-bugs.csv`.
3. Check out buggy and fixed revisions with `scripts/checkout/checkout-bug.sh`.
4. Export Defects4J metadata with `scripts/checkout/export-metadata.sh`.
5. Run the baseline with `scripts/run/baseline.sh`.
6. Run the configured, immutable Lang-1 smoke pilot (which also validates the
   generated JUnit suites on both revisions):
   `python3 scripts/run/run-lang1-smoke.py --config experiments/configs/lang1-smoke.yaml --buggy-worktree worktrees/Lang/1/b --fixed-worktree worktrees/Lang/1/f --results-root results/raw/Lang/1/differential-v3`.
7. Use `experiments/configs/pilot.yaml` only for the later repeated pilot plan.

## Reproducibility rules

- Never use deprecated bugs.
- Record project, bug ID, revision, focal method, tool/model version, seed, budget,
  start/end time, and command for every run.
- Evaluate generated tests on both the fixed and buggy revisions.
- Treat a test as a fault detector only when it passes on fixed and fails on buggy.
- Keep source code, generated tests, prompts, configuration, raw results, and summaries.
