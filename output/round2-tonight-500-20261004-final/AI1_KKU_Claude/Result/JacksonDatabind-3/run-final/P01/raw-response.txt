- Normal case: JSON array of strings (`["a","b","c"]`) deserializes to matching `String[]`, preserving order and length.
- Empty array `[]` deserializes to zero-length `String[]`.
- Array containing JSON null elements (`["a", null, "b"]`) should map null to `null` in output array, not throw.
- Single scalar string value (not wrapped in array) via `handleNonArray` path: with UNWRAP_SINGLE_VALUE_ARRAYS enabled should produce single-element array; disabled should throw `MismatchedInputException`/`JsonMappingException`.
- Empty string `""` as scalar input: behavior depends on `ACCEPT_EMPTY_STRING_AS_NULL_OBJECT`/coercion config—should yield `null` or empty array per config, not crash.
- Custom `_elementDeserializer` set via `createContextual` (e.g., with a custom String deserializer or annotation-driven contextual config) must be invoked for each element — triggers `_deserializeCustom` path.
- `deserializeWithType` with type id wrapping should delegate correctly to typed deserialization, still producing `String[]`.
- Non-string scalar JSON values inside the array (numbers, booleans) should be coerced to their String representation per `StringDeserializer` semantics, not throw, unless coercion disabled.
- JSON object as array element or as whole input should throw `MismatchedInputException` appropriately.
- Verify receiver is `StringArrayDeserializer.instance` or constructed via no-arg constructor; deserialization triggered by `ObjectMapper.readValue` into `String[].class`.
