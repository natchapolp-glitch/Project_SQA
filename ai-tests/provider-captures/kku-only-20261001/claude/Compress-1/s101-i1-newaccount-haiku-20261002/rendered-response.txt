Notes on Test Design

JUnit 3.8.2 Compatibility: Tests use TestCase and setUp()/tearDown() pattern, avoiding JUnit 4+ annotations.

Constructor Coverage: Tests validate both single-parameter and dual-parameter constructors with all format types.

Format Validation: Invalid format (999) properly rejected with IllegalArgumentException.

State Management: Tests verify closed stream behavior prevents operations; ensureOpen() throws expected IOException.

Boundary Conditions:

Zero-length writes
Array offset/length validation (negative, out-of-bounds)
Size mismatches detected on close

CRC Handling: NEW_CRC format validates CRC calculation and fails when mismatched.

Entry Lifecycle: Tests cover duplicate name detection, entry closing, automatic entry closure on next entry.

Write Semantics: Validates both write(byte[], int, int) and write(int) methods.

Finish/Close Idempotency: Multiple calls produce consistent output.

Complete Workflows: Multi-entry archives demonstrate real usage patterns.

References:

Apache Commons Compress source code (provided)
JUnit 3.8.2 API: junit.framework.TestCase
CPIO format constants: CpioConstants interface
